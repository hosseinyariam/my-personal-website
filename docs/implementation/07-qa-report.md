## ۵. ممیزی امنیت

| الزام | وضعیت | شاهد |
|---|---|---|
| CSRF روی همه‌ی POSTها | ✓ | پیش‌فرض Laravel + تست فرم |
| XSS — پاکسازی HTML ورودی | ✓ | `dehydrateStateUsing(Str::sanitizeHtml)` + تست |
| Mass Assignment | ✓ | `$fillable` صریح روی ۲۵ مدل |
| کنترل دسترسی سرور-ساید | ✓ | ۲۱ Policy + `canAccessPanel` + تست ۴۰۳ |
| فهرست مجاز مدیر | ✓ | `ADMIN_EMAIL`؛ خالی = قفل، نه باز (تست‌شده) |
| Rate Limiting | ✓ | ورود ۵/دقیقه، تماس ۵/ساعت، جست‌وجو ۳۰/دقیقه |
| امنیت Upload | ✓ | MIME واقعی + `getimagesize` + نام تصادفی + سقف ۵MB |
| Secrets | ✓ | `encrypted` cast؛ جدول `settings` راز نمی‌پذیرد (تست‌شده) |
| SSRF | ✓ | `SsrfGuard` با ۱۹ بازه‌ی ممنوع + تست ۱۰ URL خطرناک |
| هدرهای امنیتی | ✓ | CSP، HSTS، `X-Frame-Options: DENY`، nosniff، Referrer-Policy |
| Session | ✓ | `secure` + `httpOnly` + `sameSite` + `encrypt` در تولید |
| پنهان‌سازی خطا | ✓ | `shouldRenderJsonWhen` + صفحات سفارشی ۴۰۴/۴۰۳/۴۱۹/۴۲۹/۵۰۰/۵۰۳ |
| `.env` بیرون docroot | ✓ | چیدمان انتشار (سند ۰۸) |
| Indexing پنل | ✓ | middleware `NoIndexAdmin` + robots.txt + تست |

**نکته‌ی مهم:** چهار مورد (SSRF، هدرهای امنیتی، Session، Cron) در **هیچ‌کدام**
از ۱۱ سند پروژه مشخص نشده بودند. این‌ها شکاف مستنداتی بودند که دستورالعمل
بخش ۱۱ الزام کرده بود و پیاده شدند.

## ۹. آنچه هنوز نیازمند تأیید مالک است

هیچ‌کدام از این‌ها اجرا نشده — طبق §۱۵ دستورالعمل که «هیچ Deployment
نهایی را بدون تأیید من اجرا نکن» را الزام کرده:

1. سوئیچ نسخه‌ی PHP دامنه به ۸.۳
2. ساخت دیتابیس روی هاست
3. آپلود کد (اولین استقرار واقعی)
4. اجرای migration و seed روی تولید
5. فعال‌سازی cron
6. ورود اعتبارنامه‌های واقعی در `.env` هاست
7. ورود محتوای واقعی (پروفایل، پروژه‌ها، محصولات)
